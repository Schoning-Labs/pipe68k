pipe68k Primer

A first read before the full walk through the project. What a 68k CPU is, how pipe68k is built, and three pieces of the real Verilog explained line by line.

1. Verilog in five ideas

Verilog looks like a programming language, but it describes hardware. Nothing runs line after line. Every line becomes a circuit, and all circuits work at the same time.

  1. Modules. A module is a chip part with input and output pins. Modules are placed inside other modules, like boards with chips on them.
  2. Wires are logic. wire x = a & b; is an AND gate. Its output changes as soon as a or b changes. Long chains of such logic take time to settle, measured in nanoseconds.
  3. Registers are memory. Inside always @(posedge clk), every <= is a flip-flop. It stores a value and only changes on the rising edge of the clock. All flip-flops in the chip change at the same moment.
  4. The clock sets the speed. At 66.67 MHz the clock ticks every 15 ns. The logic between two flip-flops must settle within those 15 ns. "Timing closure" means every such path fits.
  5. Bit vectors. [31:0] is 32 bits, bit 31 on the left. x[7:0] is the low byte. {a, b} joins bits. {32{s}} repeats bit s 32 times.

In an FPGA, the logic becomes small lookup tables (LUTs, 4 inputs each on this chip) wired together. The Tang board's chip has about 138,000. That is why the logic size of each unit matters so much.

2. The 68k as a programmer sees it

D0–D7
Eight 32-bit data registers. Arithmetic works on bytes (.B), words (.W, 16 bits) or longs (.L, 32 bits).
A0–A7
Eight 32-bit address registers. A7 is the stack pointer. Memory is reached through them.
PC
Program counter: the address of the next instruction.
CCR
Condition flags X N Z V C, set by most instructions and tested by branches.

Instructions are 2 to 22 bytes long. The first 16-bit word says what to do. Extension words follow with constants and addresses. This variable length is what makes a fast 68k hard: the CPU does not know where the next instruction starts until it has decoded the current one.

The 68020 adds 32-bit everything, more addressing modes, bit-field instructions and a coprocessor interface for the 68881/68882 FPU. pipe68k implements the 68020 instruction set plus the 68882.

3. How pipe68k is built

A pipeline

A simple CPU does one instruction from start to end, then the next. pipe68k works like an assembly line. Each stage does one part of the work in one clock, then passes the instruction on. Eight instructions are in progress at once.

IFFetch: read code from the 8 KB instruction cache into a queue
DSDecode: turn instructions into micro-operations (uops)
DRDecide which two instructions can run together
AGAddress: compute memory addresses
OC1Read the 8 KB data cache
OC2Align data, read registers
EXExecute: add, shift, compare, branch
WBWrite back: registers, memory, flags

Uops. A complex 68k instruction such as MOVEM (save many registers) is broken into simple steps, one uop each. Most instructions are a single uop. A uop is a 268-bit bundle of control bits that tells every later stage what to do.

Speculation and replay. The pipeline guesses ahead: which way a branch goes, that the data is in the cache. When a guess is wrong, the instructions behind it are thrown away and restarted. Results only become final in WB, in program order, so software never sees the guess.

Dual issue: two instructions per clock

This is the main goal of the project. It follows the design of Motorola's 68060.

  • Lane A can execute every instruction.
  • Lane B executes only simple, one-uop instructions between registers: MOVE, ADD, SUB, AND, OR, CMP, MOVEQ, ADDQ, TST, CLR, predicted branches and a few more.
  • Two instructions pair only when the second does not need a result the first one is still computing. DR checks this every clock. Section 4.3 shows that check.

The FPU

The floating-point unit runs at half the CPU clock. Each floating-point operation takes many clocks anyway, so the slower clock costs little and gives its long logic paths twice the time. It was recently made smaller by doing its work in more, simpler steps.

4. Three pieces of the real code

These are short extracts from the source. Comments starting with // are added for this primer. Lines not needed to understand the idea are left out and marked.

4.1 The data registers: storing and reading D0–D7

The register file holds the CPU's registers in flip-flops. This extract shows the eight data registers: how WB writes them, and how a later stage reads them.

rtl/core/p68_regfile.v (extract)


Why two write ports? With dual issue, lane A and lane B can each finish an instruction in the same clock. Both results must be stored in that one clock.


Why the bypass? Without it, an instruction that needs the result of the one just ahead would wait one clock. With it, the value goes straight from WB to the reader.



4.2 The adder and the flags


One adder in EX does ADD, SUB, CMP, NEG, ADDX and SUBX. Subtraction is done by adding the inverted number plus one (two's complement). The flags come out of the same adder.


rtl/core/p68_ex.v (extract)


A branch such as BGT then needs one decision: is the condition true for the current flags? There are only 16 conditions and 16 flag combinations, so the code turns each condition into a small truth table.


rtl/core/p68_ex.v (extract)


The timing trick. Computing the condition from scratch takes several logic levels. Making the 16-entry table one clock early leaves only a single 16-way select in the critical clock. "Compute early into a register, select late" is used all over this core to meet 15 ns.



4.3 The pairing check: may two instructions run together?


Every clock, DR looks at the next two instructions and decides whether lane B can take the second one. This is the heart of dual issue.


rtl/core/p68_ag.v (extract, simplified)


What a failed pairing costs. Nothing beyond the lost second slot. The first instruction runs alone in lane A, and the second becomes the first of the next pair.



5. Words used in this project




LUT
Lookup table: the FPGA's basic logic block, any function of 4 inputs.


Flip-flop (FF)
One stored bit that changes on the clock edge.


Block RAM
Fixed memory blocks in the chip. Free logic when a table can live there.


Logic levels
LUTs in a row between two flip-flops. At most about 8 fit in 15 ns here.


Fanout
How many inputs one signal drives. High fanout means long, slow wires.


Place and route
Gowin's tool deciding where each LUT sits on the chip and how wires run.


CPI
Clocks per instruction, averaged over a test program.


Lockstep test
The simulated CPU runs next to a reference 68k model; every result is compared.


Replay
Throwing away and restarting instructions after a wrong guess.
